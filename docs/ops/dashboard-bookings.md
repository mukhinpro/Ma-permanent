# Дашборд — часть по записям (Wix Bookings)

**Работает сейчас, без ожидания одобрений Google.** Проверено 13 сентября.

## Как снять данные

Запрос через Wix MCP (`CallWixSiteAPI`), siteId `82c17ef9-aab3-4ced-b0e3-cce76ff1dfff`:

```
POST https://www.wixapis.com/_api/bookings-reader/v2/extended-bookings/query
{"query": {"paging": {"limit": 40},
           "sort": [{"fieldName": "createdDate", "order": "DESC"}]},
 "withEcomOrder": true}
```

Ответ длинный и обрезается на 50 000 символов — это нормально, парсер это переживает.
Сохранить ответ в файл и прогнать:

```
python3 scripts/parse-bookings.py <файл>
```

## Что видно в данных

| Поле | Что означает |
|---|---|
| `title` | услуга |
| `createdDate` | когда запись создана (не когда приём) |
| `platform` + `actor` | **`WEB` + `CUSTOMER`** = клиент записался сам через сайт. **`MOBILE_APP` + `BUSINESS`** = запись завела Alena руками |
| `totalPrice.amount` | сумма |
| `status` | `CONFIRMED` — подтверждена. **`CREATED` — оформление брошено на полпути** |
| `paymentStatus` | `PAID` / `PARTIALLY_PAID` (депозит онлайн) / `NOT_PAID` (платит на месте) |

## Что из этого следует

1. **Сайт даёт примерно треть записей**, остальное салон заводит руками. Это уточняет
   старое предположение из `docs/google-ads/state.md`, что клиенты уходят записываться
   в директ: часть действительно оформляется на сайте.
2. **Брошенные оформления видны поимённо.** Это та самая «слепая зона»: человек дошёл
   до оплаты и ушёл. Метрика для дашборда — сколько оформлений брошено за неделю.
3. **Поля «откуда узнали» в данных нет.** Открытая задача спрашивать это у клиенток
   и фиксировать в Wix остаётся актуальной — иначе связать запись с рекламой нечем.
